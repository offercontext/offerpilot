# OfferPilot 产品待办

## 待推进：反馈学习与能力沉淀

来源：2026-08-07 四个 GitHub 项目调研（Career-ops、ai-job-search、interview-coach-skill、ResumeSkills）。

### 产品判断

OfferPilot 的证据门控、人工确认和求职闭环已经较完整。下一阶段优先补齐“外部结果回流 → 事实与故事沉淀 → 下一轮准备”的反馈学习闭环，不继续堆叠孤立入口或黑盒评分。

### 推进顺序

1. **投递事实档案与结果反馈闭环（最高优先级）**
   - 冻结实际投递使用的 JD 版本、Resume 版本和最终确认材料。
   - 记录面试阶段、结果、原始反馈和用户确认的“下次怎么做”。
   - 历史记录不可覆盖；后续建议只能引用已确认事实，并明确哪些建议尚未被结果验证。

2. **结构化面试故事库**
   - 管理事实来源、证据、STAR 结构、能力标签、适用问题、使用次数和最近使用时间。
   - 标记来源变化和需要用户补充的事实。
   - 优先复用现有面试复盘与 Knowledge，不新增割裂的 AI 生成入口。

3. **基于真实复盘的自适应练习**
   - 根据已确认的复盘问题推荐练习方向。
   - 用户主动确认后启动训练，并记录完成情况。
   - 不生成综合面试能力分，不替用户判断能力或录用概率。

4. **简历诊断与事实补充工作台**
   - 收敛为诊断、事实补充、岗位定制、版本与投递四组能力。
   - 缺少真实数字时向用户追问并确认，禁止估算或伪造指标。

5. **跟进信、感谢信草稿**
   - 仅生成可编辑草稿，保留证据引用和人工确认。

6. **批量岗位导入（最后考虑）**
   - 只处理用户主动导入的数据。
   - 不自动扫描招聘网站、不操作外部平台、不引入岗位排名或低分劝退。

### 当前边界与依赖

- “投递事实档案”依赖 JD 版本、Resume 版本和确认材料链路；当前 JD 版本分支完成并合并后再进入实现。
- “结构化面试故事库”可作为后续独立 worktree 的首个实现候选，原则上不依赖 JD 版本。
- 所有结果反馈、故事和练习建议都必须区分：用户确认事实、系统观察、尚未验证的建议。
- 不新增自动外联、不降低证据校验、不引入不可解释的成功率或能力评分。

### 暂缓事项

Pipeline Intelligence / Mission Control 等工作台扩张暂不作为下一项主线，待反馈学习闭环完成后再评估，避免在事实回流尚未建立时继续增加行动面板。
